# TASK 07 — 처리 중 이탈과 중복 요청 대응

기록일: 2026-09-30. [작업 계획](assignment-plan.md)의 TASK 07 범위다. 이 기록은 현재 작업 트리의 검증 결과이며 커밋 전 상태다.

## 구현

- 촬영과 OCR 각각에 동기 요청 게이트를 두어 빠른 연속 터치가 두 번째 네이티브 요청을 만들지 않게 했다. 재촬영·앱 비활성화 시 기존 요청을 무효화하고, 오래된 완료·실패가 현재 화면을 바꾸지 않게 했다. 상태 전환 함수도 중복 촬영과 이전 사진의 이미지 오류를 거부한다.
- 앱이 `inactive` 또는 `background`가 되면 카메라 화면을 언마운트하고 진행 중 OCR 표시를 대기 상태로 되돌린다. 복귀 시 카메라 인스턴스를 새로 만들고 권한을 재확인한다. 처리 중 사진과 원본은 유지해 재인식 또는 재촬영할 수 있다.
- Expo Camera의 임시 사진 URI를 `expo-file-system`으로 삭제한다. 촬영 이미지에서 재촬영할 때, OCR 성공 후 결과 화면으로 전환할 때, 이탈 뒤 늦게 끝난 촬영에서 삭제한다. OCR이 읽고 있는 동안에는 삭제를 미뤘다가 모든 인식 요청이 끝나면 처리한다. 과거 작업에서 남긴 캐시는 소급 삭제하지 않는다.

API 근거: [Expo Camera의 임시 사진과 프리뷰 지침](https://docs.expo.dev/versions/v57.0.0/sdk/camera/), [Expo FileSystem의 File 삭제 API](https://docs.expo.dev/versions/v57.0.0/sdk/filesystem/), [React Native AppState](https://reactnative.dev/docs/appstate).

실기기 추가 확인 절차: 카메라 촬영 버튼을 빠르게 두 번 누르고 사진이 하나만 나타나는지 확인한다. OCR 버튼을 빠르게 두 번 누르고 처리 중 홈으로 나갔다가 돌아와 사진이 유지되고 다시 인식 또는 재촬영이 가능한지 확인한다. 다른 글자의 사진으로 두 번 이상 반복해 이전 결과가 나타나지 않는지 확인한다. 각 기기에서 프리뷰 복귀와 오류 표시도 함께 기록한다.

Android USB 연결이 한 차례 끊겼으나 재연결 후 OCR 시작 직후 홈 이탈·복귀와 재인식을 확인했다. 홈 입력이 실제 네이티브 인식 완료 전이었는지는 시간 측정으로 입증하지 않았다. 복귀 화면과 재인식 결과가 예상 상태와 일치했다.

## AI 활용 기록

문제: 기존 요청 번호 가드는 재촬영 후 일부 늦은 OCR 결과만 막았고, 앱 비활성화 중 촬영·OCR 결과와 캐시 파일을 관리하지 않았다. 요청 내용: TASK 07 진행, 커밋은 하지 않기. 제안: 요청 게이트와 앱 상태별 무효화, 사진 사용 횟수 기반 지연 삭제, 중복·늦은 결과 테스트. 채택·수정: 구현 후 React 린트 규칙에 맞게 게이트·파일 관리 객체를 상태 초기화로 보관했고, 결과 화면 전환 뒤 파일을 삭제하도록 수정했다. 직접 검증: 공식 API 문서, 자동 검사·양 플랫폼 JS 번들, Android 실기기 복귀·OCR·재촬영과 캐시 파일 삭제, iPhone Release 빌드·설치·프리뷰를 확인했다. iPhone의 처리 중 이탈과 반복 촬영은 사용자가 수동으로 확인해 보고했다.
