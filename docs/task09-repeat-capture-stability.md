# TASK 09 — 양쪽 실기기 반복 촬영 안정성 검증

기록일: 2026-09-30. 사용자가 개발서버 실행과 기기 조작을 직접 수행하고 결과를 보고하는 방식으로 진행한다. 에이전트는 이 TASK에서 개발서버·앱 실행이나 기기 조작을 수행하지 않았다.

## 범위와 안내한 절차

양쪽 실기기에서 같은 한국어·영어 인쇄체 샘플을 같은 조명·거리·각도로 촬영하는 시나리오를 제공했다. 기본 흐름은 촬영 → OCR → 결과 확인 → 재촬영 20회이며, 1·5·10·15·20회차에 OCR 시간, 프리뷰 끊김, UI 응답, 발열과 이상 현상을 기록하도록 안내했다. 연속 터치, 다른 글자 샘플의 이전 결과 혼선, 프리뷰·사진·OCR 상태에서 홈 이탈 후 약 5초 뒤 복귀, 마지막 정상 촬영도 포함했다.

위 횟수와 입력 조건은 제안한 시나리오이며 실제 수행 횟수·조건으로 간주하지 않는다.

## 사용자 실기기 검증 결과

사용자는 iPhone과 Android에서 각각 10회 수행했고, 재촬영·홈 이탈·권한이 없는 경우를 처리했으며 끊김과 지연이 없었다고 보고했다. 테스트의 실행과 관찰은 사용자 수동 검증이며 에이전트가 화면이나 로그를 직접 확인하지 않았다.

| 환경 | 반복 횟수 | 사용자 보고 |
| --- | --- | --- |
| iPhone 16 Pro Max / iPhone OS 27.0 | 10회 | 재촬영, 홈 이탈, 권한이 없는 경우의 복구 확인. 프리뷰 끊김과 지연 없음. |
| `SM-A245N` / Android 16(API 36) | 10회 | 재촬영, 홈 이탈, 권한이 없는 경우의 복구 확인. 프리뷰 끊김과 지연 없음. |

기기·OS는 기존 실기기 검증 기록을 따른다. 이번 보고에서 기기·OS 변경은 전달되지 않았다. 권한 거부부터 설정 변경·복귀까지의 세부 단계와 홈 이탈 당시 OCR 완료 여부는 이번 보고에서 구분되지 않았다. TASK 06·07의 기존 검증 기록과 함께 해석한다.

### 측정하지 않거나 확인되지 않은 범위

- 제안은 20회였으나 실제 수행은 기기별 10회다. 장시간 사용이나 20회 수행으로 기록하지 않는다.
- 동일 샘플·조명·거리·각도를 사용했는지는 확인되지 않았다.
- OCR 시간은 수치로 측정하지 않았다. 지연 없음은 사용자 체감 관찰이며 OCR 시간의 평균·최댓값을 뜻하지 않는다.
- 메모리 사용량, 임시 사진 누적, 발열은 이번 테스트 결과가 확보되지 않았다. 자원 누수가 없거나 발열이 없다고 결론 내리지 않는다.
- 연속 터치와 다른 샘플의 결과 혼선은 이번 보고에서 별도로 확인되지 않았다.
- Android 재빌드 시 SDK 경로 누락 오류가 사용자 로그로 확인됐고 `ANDROID_HOME` 설정을 안내했다. 이후 실기기 테스트 결과는 확보했지만 최종 빌드 성공 로그는 확보하지 않았다.

## 관련 결함

테스트 전에 사용자는 iOS 카메라 시야가 기본 카메라 0.5×와 유사하다고 보고했다. [TASK 12](task12-ios-camera-framing.md)에서 세션 설정 뒤 배율을 재적용하도록 수정했다. 사용자는 수정 후 자연스러운 동작을 확인했다고 보고했다. 정확한 배율·거리·초점과 재촬영·홈 복귀 후 배율 유지의 개별 결과는 아직 확보하지 않았다.

## 상태

사용자는 양쪽 실기기 각각 10회에서 기능 안정성과 프리뷰·응답을 확인한 뒤 작업 완료를 선언하고 커밋·PR 생성을 요청했다. 이 검증 범위와 위 미검증 한계를 명시해 TASK 09 작업을 마무리한다. 보고된 제출 차단 문제는 없으며, 원 계획의 동일 입력 조건 확인과 메모리·발열 관찰까지 통과한 것으로 표시하지 않는다.

## 커밋 전 자동 검사

macOS 개발 환경, Node.js 24.21.0 / pnpm 12.4.2에서 `pnpm install --frozen-lockfile`, `pnpm test`(11개), `pnpm typecheck`, `pnpm lint`, `git diff --check`가 통과했다. iOS 패치 적용·Swift 문법 검사 결과는 TASK 12 기록에 있다. 자동 검사는 실기기 성능·메모리·발열을 입증하지 않는다.

## AI 활용 기록

문제: 기존 기록에는 장시간 반복 촬영과 성능·자원 관찰 결과가 없었다. 요청: TASK 09 진행, 테스트는 사용자가 직접 수행하고 에이전트는 시나리오만 제공. 제안: 동일 조건 반복 촬영과 연속 조작·이탈 복귀·성능 관찰 시나리오. 채택·수정: 사용자 조작 방식에 맞춰 절차와 보고 항목을 제공했고, 테스트 전 발견된 iOS 시야 문제는 사용자 요청에 따라 TASK 12로 수정했다. 검증 결과: 사용자가 iOS 수정 후 자연스러운 동작과 반복 테스트 중 문제 없음을 보고했다. 양쪽 각 10회, 재촬영·홈 이탈·권한 복구, 끊김·지연 없음은 사용자 후속 보고로 확보했다. 에이전트가 기기에서 직접 확인한 결과는 아니다.
