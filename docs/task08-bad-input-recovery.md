# TASK 08 — 나쁜 입력에서 재촬영 유도

기록일: 2026-09-30. [과제 원문](https://github.com/git-artinus/artinus-fe-recurit)의 나쁜 입력 처리·OCR 실패 대응과 [작업 계획](assignment-plan.md)의 TASK 08을 대상으로 한다. 사용자가 양쪽 실기기에서 네 가지 나쁜 입력 조건과 재촬영을 확인했다.

## 구현

- 카메라 화면에서 촬영 전에 밝기, 글자와의 거리, 기울기를 조정하도록 안내한다.
- OCR이 글자를 찾지 못하면 촬영 조건을 바꿔 다시 촬영하도록 안내한다. OCR 실행 오류는 미검출과 구분해 다시 인식하거나 새로 촬영하도록 안내한다. 두 상태 모두 기존 재촬영 버튼을 유지한다.
- 일부 글자가 누락되거나 잘못 인식되어도 OCR이 성공을 반환할 수 있으므로 결과 화면에서 내용을 확인하고 필요하면 다시 촬영하도록 안내한다.
- 앱은 조도·초점·기울기를 측정하지 않는다. 특정 사진이 어둡거나 흐리다고 확정하는 문구는 표시하지 않는다. 미검출 안내는 입력을 개선해 볼 수 있는 일반적인 방법이다.

| 환경 | 확인한 동작 | 아직 확인하지 못한 범위 |

### 조건별 사용자 보고

사용자는 iPhone과 Android에서 모두 다음 결과를 확인했다고 보고했다.

| 입력 | 표시·복구 결과 |
| --- | --- |
| 저조도 | 앱이 다시 촬영을 요청했고, 멈춤 없이 다시 촬영할 수 있었다. |
| 흐린 글자 | 앱이 다시 촬영을 요청했고, 멈춤 없이 다시 촬영할 수 있었다. |
| 글자 없는 장면 | 앱이 다시 촬영을 요청했고, 멈춤 없이 다시 촬영할 수 있었다. |
| 기울어진 글자 | OCR 결과가 표시됐지만 정확하지 않았다. 사용자는 다시 촬영이 가능했다고 보고했다. |

사용자는 저조도·흐린 글자·글자 없는 장면에서 다시 촬영 안내가 나왔다고 보고했으며, 그 원인이 OCR 미검출인지 실행 오류인지는 구분해 전달하지 않았다. 기울어진 글자의 실제 입력 각도, 인식 텍스트, 정면으로 다시 촬영한 뒤의 정확도는 기록되지 않았다. OCR 실행 오류는 별도 재현 방법이 확보되면 실기기에서 확인한다.

## 보정 판단

양쪽 기기에서 기울어진 글자의 결과가 부정확했다는 사용자 보고가 있다. 현재 결과 화면은 잘못 인식된 글자를 확인하고 다시 촬영하도록 안내하고, 카메라 화면은 기울기를 바로잡도록 안내한다. 이 검증에서는 촬영 조건을 고친 뒤에도 문제가 반복되는지 또는 자동 기울기 보정이 필요한지 확인하지 못했다. 따라서 TASK 08에서는 추가 이미지 보정을 구현하지 않고 이 한계를 기록한다. 정면 재촬영 후에도 정확도가 낮게 반복되면 입력 각도·원본 사진·결과를 확보해 별도 보정 작업을 계획한다.

## AI 활용 기록

문제: 기존 카메라 안내는 화면에 글자를 담으라는 내용뿐이고, 미검출·오류 문구는 나쁜 입력에서 다음 행동을 충분히 구분하지 못했다. 요청: TASK 08 진행. 제안: 촬영 전 밝기·거리·기울기 안내, 미검출과 실행 오류별 복구 문구, 조건별 실기기 검증표. 채택·수정: 실제 품질 측정이 없으므로 원인을 단정하지 않는 문구로 수정하고 기존 재촬영 경로를 활용했다. 직접 검증: 과제 원문과 코드 상태를 대조하고 자동 검사·양 플랫폼 JS 번들 생성을 실행했으며, Android 실기기에서 흐릿하고 읽을 글자가 없는 사진의 미검출 안내와 재촬영 복귀를 확인했다. 사용자는 양쪽 실기기에서 나쁜 입력 네 조건을 확인했고, 저조도·흐린 글자·글자 없는 장면의 재촬영 복구와 기울어진 글자의 부정확한 인식 결과를 보고했다.
