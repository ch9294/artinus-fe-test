# TASK 06 — 카메라 권한 거부 후 복구

기록일: 2026-09-29. 과제 원문의 카메라 권한 거부 처리와 [작업 계획](assignment-plan.md)의 TASK 06을 대상으로 한다.

## 구현

- 최초 요청 전, 재요청 가능한 거부, 운영체제에서 재요청할 수 없는 거부를 구분한다. 마지막 상태에서는 기기 설정을 여는 버튼과 카메라 허용 안내를 표시한다.
- 앱이 다시 활성화되면 `useCameraPermissions`의 세 번째 함수로 현재 권한을 다시 읽는다. 확인 중에는 이전 권한에 따른 카메라 화면을 잠시 숨기고, 확인에 실패하면 재시도 버튼을 표시한다. 설정에서 허용한 뒤 정상 응답을 받으면 앱 재시작 없이 카메라 화면으로 돌아간다.
- 권한 요청과 설정 열기에 실패했을 때 각각 오류 안내를 표시한다.

API 근거: [Expo SDK 57 Camera 권한 훅](https://docs.expo.dev/versions/v57.0.0/sdk/camera/#usecamerapermissionsoptions), [React Native AppState](https://reactnative.dev/docs/appstate), [React Native Linking.openSettings](https://reactnative.dev/docs/linking#opensettings).

실기기 절차:

1. 설치된 개발 빌드에서 카메라 권한을 거부한다. 재요청 가능하면 다시 요청 버튼, 불가능하면 설정 열기 버튼이 표시되는지 확인한다.
2. 설정 열기를 누르고 이 앱의 카메라 권한을 허용한 다음 앱으로 돌아온다. 앱을 종료하거나 다시 실행하지 않은 상태에서 프리뷰와 촬영 버튼이 돌아오는지 확인한다.
3. 정지 이미지를 촬영하고 OCR 결과까지 확인한다. 기기·OS·거부 상태와 복귀 결과를 별도로 기록한다.
4. 설정에서 다시 권한을 끄고 앱으로 돌아와 카메라가 사라지고 권한 안내가 표시되는지도 확인한다.

이번 사용자 검증은 1~3번의 설정 복구 경로를 확인했다. 4번의 복구 후 재차 권한 해제와 권한 조회 자체의 실패는 실기기에서 재현하지 않았다.

## AI 활용 기록

문제: 기존 화면은 권한을 다시 요청할 수 없는 경우 설정 안내 문장만 표시했고, 설정 변경 후 앱 복귀 시 권한을 다시 확인하지 않았다. 요청 내용: TASK 06 진행. 제안: 권한 상태별 안내, `Linking.openSettings`, 앱 활성화 시 Expo 권한 훅 재확인, 상태 분류 테스트. 채택·수정: 제안을 구현했고 권한 확인 실패 시 재시도 화면과 확인 중 이전 카메라 화면 차단을 추가했다. 직접 검증: 공식 API 문서와 설치된 훅 타입을 확인하고 정적 검사·테스트·양 플랫폼 번들 생성을 실행했다. Android 프리뷰·촬영 이미지는 직접 확인했고, 양쪽 실기기의 권한 복구와 촬영·OCR는 사용자가 수동으로 확인해 보고했다.
