## 목표

iOS와 Android에서 카메라 프리뷰 → 촬영 → 정지 이미지 OCR → 인식 결과 확인 흐름을 안정적으로 제공한다. 권한 거부, 텍스트 미검출, OCR 실패, 나쁜 입력을 처리하고 기술 선택과 테스트 근거를 README에 설명한다.

과제는 iOS/Android 기능 패리티와 실기기 성능을 평가한다. 현재 확보된 Android 실기기가 없으므로 Android 실기기 검증을 계획의 우선 위험으로 둔다. Android 에뮬레이터 검증만으로 실기기 프리뷰 성능을 검증했다고 주장하지 않는다.

## 기술 선택 방향

React Native + Expo를 우선 후보로 삼는다. 익숙한 개발 환경을 활용해 기능 완성과 실기기 검증에 시간을 배정하기 위해서다. 다만 OCR 라이브러리의 네이티브 모듈 지원, iOS/Android 빌드 가능 여부, 지원 언어를 확인한 뒤 확정한다. Expo Go에서 동작하지 않는 모듈을 사용해야 한다면 development build를 고려한다. 정확한 라이브러리와 버전은 아직 미정이다.

OCR은 온디바이스 방식을 우선 검토한다. 네트워크 의존성이 줄어드는 장점이 있지만, 대상 언어 지원과 설치 복잡도, 양 플랫폼 처리 성능을 확인한 뒤 결정한다. 인식 대상 언어와 최소 지원 OS도 기술 검증 단계에서 정한다.

## 단계별 작업

### 1. 기술 검증

- Expo 기반 iOS/Android 실행 및 카메라 권한·프리뷰 확인
- 사진 촬영 후 OCR 결과 출력
- 대상 언어, 이미지 방향, 회전, 처리 중 UI 반응 확인
- 선택한 라이브러리의 네이티브 설정과 빌드 제약 기록

첫 번째 중간 산출물은 두 플랫폼에서 촬영부터 인식까지 이어지는 최소 흐름이다. 한 플랫폼의 완성도를 먼저 높이지 않는다.

### 2. 기본 흐름과 예외 처리

- 촬영 중·OCR 중 상태 표시와 중복 실행 방지
- 결과 확인 및 재촬영
- 권한 거부·차단 상태에 맞는 안내
- 텍스트 미검출과 OCR 실행 오류 구분
- 앱 전환·화면 이탈 후 오래된 비동기 결과가 현재 화면에 반영되지 않도록 처리
- 임시 이미지와 카메라 자원 정리

### 3. 나쁜 입력 대응

- 촬영 전 조명, 거리, 기울기에 대한 간단한 안내
- 인식 결과가 없을 때 촬영 조건을 조정해 재시도할 수 있는 경로
- 실제 반복되는 문제가 확인된 경우에만 추가 보정 검토
- 이미지 품질을 측정하지 않았다면 흐림·저조도를 확정적으로 진단하지 않음

### 4. 검증

iPhone 16 Pro Max에서 iOS 실기기 검증을 수행한다. Android는 가능한 한 9/28 이전에 실기기를 빌리거나 확보한다. 확보하지 못하면 에뮬레이터로 기능·빌드를 검증하고 실기기 성능은 미검증으로 README에 명시한다. 양 플랫폼 자동 테스트는 상태 전환과 오류 분기처럼 의미 있는 부분에 집중한다.

## 범위 조절

실시간 OCR, 텍스트 수정·복사, 촬영 이력, 로그인, 복잡한 이미지 편집과 장식 중심 UI는 초기 범위에서 제외한다. 일정이 밀리면 이 항목은 추가하지 않고 기본 흐름, 양 플랫폼 패리티, 오류 처리, 실기기 확인에 집중한다.
