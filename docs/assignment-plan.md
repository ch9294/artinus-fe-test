## 목표와 현재 상태

iOS와 Android에서 카메라 프리뷰 → 정지 이미지 촬영 → OCR → 결과 확인 → 재촬영 흐름을 제공한다. 양 플랫폼 기능 패리티와 실기기에서 원활한 프리뷰, OCR 중 UI 응답을 검증한다. 권한 거부·인식 실패·나쁜 입력에서 복구되는지도 확인한다.

현재 저장소에는 Expo SDK 57, React Native, TypeScript 프로젝트와 pnpm 잠금 파일이 있다. TASK 01에서 development client 설정과 양 플랫폼 JavaScript 번들·네이티브 프로젝트 생성을 확인했다.

iPhone 16 Pro Max / iPhone OS 27.0에서 기본 앱 빌드·실행을 사용자 확인으로 기록했고 Pixel 9 에뮬레이터 / Android 16(API 36)에서 기본 앱 빌드·설치·화면 실행을 직접 확인했다.

iPhone 카메라 촬영과 텍스트 OCR 동작은 사용자가 확인했고 Android 실기기 `SM_A245N` / Android 16(API 36)에서 빌드·설치·카메라 프리뷰 및 OCR 동작도 확인했다. OCR 샘플의 언어·인쇄체·입력 조건은 아직 기록되지 않았다.

Android 실기기 촬영 사진의 방향·화질과 iOS 근접 초점 수정은 아직 검증하지 않았다.

계획 수립 시 Xcode 앱은 설치되어 있었지만 활성 개발 도구 경로는 Command Line Tools였다. Android Studio, 기본 경로의 Android SDK, PATH의 adb, Java 런타임은 확인되지 않았다. TASK 01에서 실제 설치·선택·서명 상태를 다시 확인한다.

## 기술 선택과 범위

기존 Expo 프로젝트로 development build를 구성한다. 카메라와 OCR의 구체적인 라이브러리·버전·최소 지원 OS는 공식 문서와 양 플랫폼 동작을 확인한 뒤 결정한다. OCR 엔진은 TASK 04에서 한국어·영어 지원, 네이티브 빌드 호환성, UI 비차단 여부를 검증한 후 확정한다.

저조도·블러·기울기는 촬영 안내, 미검출·실패 처리, 재촬영으로 우선 대응한다. 실제 입력 테스트에서 부족한 점이 확인되면 보정을 검토한다. 이미지 품질을 측정하지 않았다면 흐림이나 저조도를 확정적으로 진단하지 않는다.

손글씨 인식 보장, 실시간 OCR, 텍스트 수정·복사, 촬영 이력, 로그인, 복잡한 이미지 편집, 장식 중심 UI는 범위에서 제외한다.
