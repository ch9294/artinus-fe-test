# TASK 05 — 결과 확인과 재촬영

기록일: 2026-09-29. 과제의 촬영 → 정지 이미지 OCR → 결과 확인 흐름과 계획 문서의 TASK 05를 대상으로 한다.

## 구현

- OCR 성공 시 촬영 이미지 확인 화면에서 결과 전용 화면으로 전환한다. 결과 텍스트는 가용 높이를 사용하는 `ScrollView`에서 표시하고 하단의 다시 촬영 버튼은 스크롤 영역 밖에 둔다. 한 언어만 실패한 경우의 안내도 결과 화면에 유지한다.
- 카메라·촬영 이미지·결과를 하나의 상태 전환 함수로 관리한다. 재촬영 시 사진 URI, 이미지 표시 오류, OCR 상태·결과를 초기화한다. 카메라 시작 오류도 초기화하고 프리뷰를 새로 시작한다.
- 기존 OCR 요청 번호 가드를 유지한다. 재촬영 전 요청의 늦은 응답은 무시하며, 상태 전환 함수도 촬영 이미지 화면을 떠난 뒤 도착한 OCR 완료 이벤트를 무시한다. 처리 중 이탈·중복 요청의 전 범위는 TASK 07에서 검증한다.

## 검증

| 환경 | 확인한 동작 | 아직 확인하지 못한 범위 |
| --- | --- | --- |
| macOS 개발 환경, Node.js 24.21.0, pnpm 12.4.2, Expo SDK 57 | `pnpm install --frozen-lockfile`, `pnpm test`(5개 통과), `pnpm typecheck`, `pnpm lint`, iOS·Android JS 번들 생성, `git diff --check` 통과. 상태 테스트에서 긴 결과 보존, 두 번째 촬영 결과 분리, 오류 초기화, 이전 결과 무시를 확인했다. | 기기에서의 긴 텍스트 스크롤 및 결과 화면 배치. |
| `SM_A245N` / Android 16(API 36), 1080 × 2340 | 개발 빌드에 새 JS 번들을 연결했다. 글자 없는 장면의 촬영 → OCR 미검출 → 다시 촬영, 이어서 한영 인쇄체 책 표지의 인식 결과 표시 → 다시 촬영 → 다른 본문 페이지 인식 결과 표시를 확인했다. 두 번째 결과에는 첫 번째 표지 문구가 남지 않았다. 결과 화면의 텍스트 영역과 하단 버튼 배치를 스크린샷으로 확인했다. | 본문 OCR 결과 약 20줄은 한 화면에 모두 표시되었다. 화면 높이를 넘는 결과의 실제 스크롤은 아직 확인하지 않았다. 인식 정확도 평가는 수행하지 않았다. |
| iPhone 16 Pro Max / iPhone OS 27.0 | `devicectl`로 실기기 연결과 현재 OS 버전을 확인했다. 사용자가 LAN 개발 빌드에서 촬영 → OCR 결과 표시 → 화면 높이를 넘는 긴 결과의 마지막 줄까지 스크롤 → 다시 촬영을 완료했다고 보고했다. 다른 문장으로 두 번째 촬영·인식 후 첫 번째 문장이 남지 않고 오류 없이 다시 촬영했다고 추가 보고했다. | 이는 사용자 수동 검증 보고이며 에이전트가 iPhone 화면·인식 텍스트를 직접 읽은 결과는 아니다. |

실기기 확인 절차: 한글·영문 인쇄체 여러 줄이 들어간 지면을 촬영하고 텍스트 인식을 누른다. 결과 화면에서 첫 줄·마지막 줄까지 스크롤한 뒤 다시 촬영을 누른다. 다른 문장을 촬영·인식해 이전 문장·오류가 남지 않는지 확인한다. 같은 절차를 iPhone과 Android에서 수행하고 기기·OS·입력·결과를 기록한다.

## AI 활용 기록

문제: 기존 결과가 촬영 이미지 아래의 높이 180px 영역에 놓여 긴 텍스트 확인이 불편하고, 재촬영 초기화가 여러 상태 변수에 분산되어 있었다. 요청: 이전 작업을 읽고 TASK 05를 이어서 구현. 제안: 결과 전용 스크롤 화면과 촬영 흐름 상태 전환 함수를 작성하고 반복 촬영 테스트를 추가. 채택·수정: 결과 화면과 전환 함수를 채택했다. 직접 검증: 상태 테스트와 정적 검사, 양 플랫폼 번들 생성을 실행했고 Android 실기기에서 미검출 후 재촬영 및 서로 다른 두 인쇄체 결과를 확인했다. 사용자는 iPhone 실기기에서 긴 결과 스크롤과 두 번 연속 인식·재촬영을 확인했다고 보고했다.
