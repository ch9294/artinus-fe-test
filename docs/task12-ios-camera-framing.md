# TASK 12 — iOS 카메라 기본 시야 보정

기록일: 2026-09-30. TASK 09 반복 안정성 검증 전에 발견된 결함이다. TASK 04의 근접 초점 패치와 관련되며, 사용자는 수정 후 iPhone에서 자연스러운 동작을 확인했다고 보고했다.

## 증상과 진단

사용자는 iPhone의 앱 카메라가 기본 카메라 앱의 0.5×와 유사하게 보이고 가까운 글자도 작게 보인다고 보고했다. Android에서는 자연스럽게 보인다고 보고했다. 이는 사용자 수동 비교이며 실제 렌즈 종류와 내부 배율을 측정한 결과는 아니다.

TASK 04 패치는 iOS 기본 후면 카메라를 단일 광각에서 트리플·듀얼 와이드 가상 카메라로 변경했다. 기본 시야는 첫 렌즈 전환 기준 배율로 보정하도록 구현했지만, 배율 적용은 카메라 입력 추가 시점에만 수행됐다. 원본 `expo-camera@57.0.5`에서 그 이후 사진용 세션 프리셋이 적용되는 순서를 확인했다.

[Apple 활성 포맷 문서](https://developer.apple.com/documentation/avfoundation/avcapturedevice/activeformat)는 세션 프리셋이 입력 기기의 활성 포맷을 설정한다고 설명한다. 이 설정 이후 배율이 유지되지 않을 가능성을 수정 대상으로 삼았다. 실제 기기의 설정 전후 배율을 측정하지 않았으므로, 배율 초기화가 원인으로 확정된 것은 아니다.

## 수정

- 기존 iOS 가상 카메라 선택과 연속 자동 초점 처리를 유지한다.
- 초기 사진 세션의 설정 커밋 후 `updateZoom()`을 다시 실행한다.
- 카메라 모드 전환과 개별 프리셋 변경에서도 설정 커밋 후 배율을 다시 적용한다. 외부 구성 블록 안에서 프리셋을 변경하는 경로는 해당 블록의 커밋 뒤에 적용한다.
- `pnpm-lock.yaml`의 패치 해시를 갱신했다. Android와 JavaScript 앱 코드는 변경하지 않았다.

## 검증 결과와 한계

macOS 개발 환경, Node.js 24.21.0 / pnpm 12.4.2에서 공식 npm 배포본 `expo-camera@57.0.5`를 임시 디렉터리에 읽어 패치를 검증했다. `git apply --check`와 실제 패치 적용, `xcrun swiftc -frontend -parse`로 두 Swift 파일의 문법 확인, `pnpm install --lockfile-only --ignore-scripts`, `git diff --check`가 통과했다.

Swift 문법 검사는 네이티브 타입 검사나 앱 빌드 성공을 입증하지 않는다. 에이전트는 앱 빌드·설치·실행, 개발서버 실행, 기기 조작을 수행하지 않았다. 사용자는 수정 후 iPhone에서 자연스러운 동작을 확인했다고 보고했다. 정확한 1× 시야 비교, 거리별 초점, 재촬영·홈 복귀 시 배율 유지의 개별 결과는 아직 확보하지 않았다. 이 수정으로 TASK 09가 완료되지는 않는다.

## 사용자 실행·확인 절차

네이티브 패치이므로 Metro 새로고침만으로는 적용되지 않는다. 이 워크트리에서 다음 순서로 실행한다.

```sh
pnpm install --frozen-lockfile
pnpm ios
```

1. 같은 위치에서 같은 글자를 앱과 iPhone 기본 카메라의 1×로 비교한다. 프리뷰 종횡비가 다를 수 있으므로 전체 화면의 완전 일치보다 글자 크기와 주변 시야를 비교한다.
2. 약 20~30cm 거리에서 촬영하고 프리뷰·촬영 사진·OCR을 확인한다.
3. 약 5~10cm로 가까이 이동해 1~2초 기다린 뒤 초점과 글자 크기를 확인하고 촬영·OCR을 수행한다. 해당 거리에서 선명함을 보장하는 것은 아니며 실제 결과를 기록한다.
4. 결과에서 재촬영 3회, 홈 이탈 후 복귀 1회 뒤 시야가 다시 0.5× 수준으로 바뀌지 않는지 확인한다.
5. 계속 0.5× 수준이면 보정 실패로 기록한다. 다음 진단에서는 입력 추가·세션 커밋 후의 기기 종류, 렌즈 전환 기준, 실제 배율을 비교한다.

## AI 활용 기록

문제: 근접 초점 패치 이후 iOS 시야가 기본 카메라 0.5×와 유사하다는 사용자 보고. 요청: 먼저 원인을 조사한 후 코드 수정. 제안: 세션 설정 이후 기본 시야 배율 재적용. 채택·수정: 초기 설정, 모드 전환, 개별 프리셋 변경의 커밋 이후에 배율을 다시 적용하고 잠금 파일을 갱신했다. 직접 검증: 원본 배포 소스·공식 API 문서 비교, 패치 적용과 Swift 문법 검사. 기기 화면 비교와 수정 후 자연스러운 동작 확인은 사용자 수동 보고이며 에이전트의 수정 후 빌드·기기 검증은 미수행이다.
